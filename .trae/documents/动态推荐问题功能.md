# 动态推荐问题功能

## Context（背景）

当前推荐问题是 `ChatView.vue` 第 192-206 行**硬编码**的 3 个固定问题（"什么是 Agentic RAG？""解释变压器原理""写快速排序"），只在空状态显示，且与用户上下文完全无关。

用户希望推荐问题**动态化、个性化**：
1. **空对话状态**：基于可用知识库 + 长期记忆，用 LLM 生成 3 个入门引导问题
2. **回答完成后**：基于【长期记忆 + 当前知识库 + 上一轮问答】，用 LLM 生成 3 个深入后续问题

核心目标：让推荐问题真正反映"用户可能想问什么"，而非静态文案。

## 设计方案

### 两种生成模式
- **guide（引导模式）**：空对话触发。上下文 = 知识库列表 + 长期记忆（按重要性取前 5 条）。生成入门问题。
- **recommend（推荐模式）**：回答完成后触发。上下文 = 上一轮问答 + 当前知识库 + 长期记忆（用上轮问题做语义检索）。生成深入后续问题。

### 后端

**新增端点 `POST /api/v1/chat/suggestions`**（追加到 `backend/app/api/v1/chat.py`，与 `/chat/stream` 同文件）

请求/响应 schema 新增到 `backend/app/domain/schemas.py`：
- `SuggestionRequest`: `mode`(guide|recommend), `conversation_id?`, `kb_id?`, `last_question?`, `last_answer?`
- `SuggestionResponse`: `questions: list[str]`, `mode`, `fallback: bool`

**新增 service 方法 `ChatService.generate_suggestions()`**（`backend/app/services/chat_service.py`）：
- 收集上下文：`container.sqlite.kb_list()` 取知识库列表，格式化成「名称 - 描述」文本
- recommend 模式：优先用前端传的 `last_question/last_answer`，缺失则从 `conversation_service.get_messages(conv_id)` 倒序取最近一对 user/assistant
- 加载长期记忆：guide 模式用 `mem_all()` 按重要性×访问次数排序取前 5 条（无 query 无法向量检索）；recommend 模式用 `load_long_term_memories(query=last_question, ...)` 做语义检索（复用 `backend/app/rag/memory.py:41` 现有函数）
- 调 LLM：`ChatOllama(temperature=0.7)` + `with_structured_output(SuggestionQuestions)`（参考 `_run_plain_llm` 第 400 行的 LLM 构造方式）
- 失败兜底：`try/except` 捕获后返回静态问题 + `fallback: true`
- `last_answer` 截断到 1500 字防止 num_ctx 爆炸

**新增提示词**（追加到 `backend/app/rag/prompts/legal.py`）：
- `SUGGESTION_GUIDE_PROMPT`：输入知识库列表 + 记忆，要求生成 3 个 10-30 字、自包含、覆盖不同维度的入门问题
- `SUGGESTION_RECOMMEND_PROMPT`：输入上轮问答 + 知识库 + 记忆，要求生成 3 个紧扣上轮内容的深入问题，禁止指代上轮（"基于上面的回答"）
- 输出 JSON `{"questions": [...]}`，与 `MEMORY_EXTRACTION_PROMPT` 风格一致

**新增结构化输出模型**（`backend/app/rag/schemas.py`）：
- `SuggestionQuestions`: `questions: List[str]`

- **空状态布局改为两部分**（`kbList` 已在组件中通过 `loadKBs()` 获取，直接复用）：

## 边界情况
| 场景 | 处理 |
|------|------|
| 无知识库（guide） | kb_info 为"(暂无知识库)"，仍调 LLM 生成通用问题；无记忆则返回静态兜底 |
| LLM 失败/超时 | 后端 except 返回 `fallback:true` + 静态问题；前端照常渲染 |
| 切换会话 | `loadMessages` 调 `clearSuggestions`，再按有无消息触发 guide/recommend |
| 流式 abort | `aborted` 标志位，finally 不触发 recommend |
| clarification 回复 | `last.metadata?.node === 'clarification'` 时不触发 recommend |
| 重复 guide 请求 | store 内 `suggestionsMode==='guide'` 且已有数据则跳过 |
| 回答过长 | 后端截断 last_answer 到 1500 字 |

## 验证步骤
1. 后端改完后用 curl 验证 `POST /api/v1/chat/suggestions` 两种模式返回 3 个问题
2. 前端空状态：显示基于知识库的引导问题（非硬编码），切换知识库后引导问题变化
3. 发问 → 回答完成后，消息底部自动出现 3 个推荐后续问题（紧扣上轮问答）
4. 中途 abort → 不出现推荐
5. 切换历史会话 → 旧推荐清空，按会话内容重新生成
6. 关闭 Ollama → 走静态兜底问题
